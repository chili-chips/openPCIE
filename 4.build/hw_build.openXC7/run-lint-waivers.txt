# Accepted lint findings, read by run-lint.sh.
#
# One waiver per line:  <phase> <regex>
#   <phase>  tags | verilator | yosys | reset | ram | iob | slang | verible |
#            cdc | check-timing | methodology
#   <regex>  extended regex (grep -E), matched against one finding line as it
#            appears in <phase>.all of a run-lint.sh work directory
# A finding that matches is waived. Put the reason on a comment line above it.
#
# Guideline: resolve a finding at its root; waive only as the last resort.
# Work down this list and stop at the first step that applies:
#   1. Dead logic in our RTL: delete it (unused signals, registers, ports).
#      Check first that nothing uses it in another configuration (x1/x4
#      generate branches), and prove the change with run-leq.sh.
#   2. Oversized buses in our RTL: size them to what is used (PCIE_LANES,
#      data width) instead of carrying unused bits or lanes.
#   3. Unused outputs of hard macros, primitives and third-party cores, which
#      we cannot change:
#        a single pin             .PIN (/*LINT:OK*/)
#        part of a bus pin        .PIN ({NC_name, used})
#        a pin of an unused lane  route it to an NC_ signal in the lane's
#                                 generate branch
#      NC_ means no-connect: driven by such an output and never read. Do not
#      give an NC_ name to anything else.
#      Descriptor signals -- a header DW or sideband of a pcie_pkg struct type,
#      named *_dw0 ... *_dw3, *_hdr_* or *_tuser -- read only the fields the
#      logic needs; their unread fields are waived by that name. A descriptor
#      signal that is not read at all is still reported.
#   4. Unused inputs: tie them off. Exception: GT refclk inputs stay open
#      (nextpnr rejects a constant there), with a comment saying so.
#   5. Only then a waiver in this file: for findings with no source line of
#      ours (generated code, Vivado reports) or a proven tool false positive.
#      Each one is reviewed, names the file and the signals (never a whole
#      file or warning class), and has its reason on a comment line above.
#
# The inline forms are checked: the tags phase flags a /*LINT:OK*/ that is
# not on an output.

# No-connect signals (step 3): unused by design, so every NC_ name is waived
verilator ^%Warning-UNUSEDSIGNAL: .*'NC_[A-Za-z0-9_]+'

# PeakRDL passthrough cpuif: stall and error outputs are always generated; our
# mem bus has no stall or error path (reviewed 2026-10-12)
verilator ^%Warning-PINCONNECTEMPTY: src/soc_csr\.sv:[0-9]+:[0-9]+: .*'s_cpuif_(req_stall_wr|req_stall_rd|rd_err|wr_err)'$

# GTPE2_COMMON refclk inputs left open on purpose: nextpnr rejects a constant
# on a GT refclk input; only GTREFCLK0 is used (reviewed 2026-10-12)
verilator ^%Warning-PINCONNECTEMPTY: src/pcie/gtp_wrapper\.sv:[0-9]+:[0-9]+: .*'(GTGREFCLK[01]|GTREFCLK1|GTEASTREFCLK[01]|GTWESTREFCLK[01])'$
slang ^src/pcie/gtp_wrapper\.sv:[0-9]+:[0-9]+: warning: input port '(GTGREFCLK[01]|GTREFCLK1|GTEASTREFCLK[01]|GTWESTREFCLK[01])' is explicitly connected to nothing

# PeakRDL regblock internals: error-response logic that is only read when
# regblock runs with --err-if-bad-addr / --err-if-bad-rw, which we do not use
# (reviewed 2026-10-12)
verilator ^%Warning-UNUSEDSIGNAL: csr\.sv:[0-9]+:[0-9]+: Signal is not used: '(decoded_err|is_valid_addr|is_valid_rw)'

# AXI-Stream fields kept to the standard: the SOC does not read the RX tkeep
# and tuser (pcie_rx_tuser_t); on TX only tkeep[7] (upper DW valid) maps to TRN rem
# (reviewed 2026-10-12)
verilator ^%Warning-UNUSEDSIGNAL: src/pcie/axis_if\.sv:[0-9]+:[0-9]+: (Signal is not used: 'tkeep'|Bits of signal are not used: 'tkeep'\[6:0\]|Signal is not used: 'tuser')$

# PIPE tx_ctrl.reset: not used by the RTL PHY, read by the co-sim PHY model
# (5.sim/models/phy_top.EP-PIPE-BFM.sv) (reviewed 2026-10-12)
verilator ^%Warning-UNUSEDSIGNAL: src/pcie/pipe_if\.sv:[0-9]+:[0-9]+: Bits of signal are not used: 'tx_ctrl'\[5\]$

# Descriptor signals (step 3): pcie_pkg header DWs and sideband, partial field
# use by design, also as function arguments (pcie_pkg's TLP size functions);
# whole-signal "not used" is still reported
verilator ^%Warning-UNUSEDSIGNAL: .*Bits of (signal|function variable) are not used: '([A-Za-z0-9_]*_hdr_[A-Za-z0-9_]*|[A-Za-z0-9_]*_dw[0-3]|[A-Za-z0-9_]*_tuser)'

# csr.sv is generated (PeakRDL regblock --rt-read-response): its 1-stage
# write-after-read stall register, cpuif_req_stall_sr, shifts out by 1 on purpose
slang ^csr\.sv:[0-9]+:[0-9]+: warning: shift count of .32.d1. overflows 1-bit operand \[-Wshift-count-overflow\]$

# pcie_pkg header layouts kept as reference, not used by the RTL at present
# (user, 2026-11-27): the tlp_type codes
verilator ^%Warning-UNUSEDPARAM: src/pcie/pcie_pkg\.sv:[0-9]+:[0-9]+: Parameter is not used: 'TLP_TYPE_(CPL|CFG)'$

# PIPE clock mux select: pipe_clk_sel_q drives the BUFGCTRL S0/S1 that switch
# pipe_clk between 125 and 250 MHz; the XDC false-paths S0/S1 and makes the
# two muxed clocks physically exclusive, as in Xilinx's pipe_clock
# (reviewed 2026-10-13)
cdc CDC-13 +Critical .* u_pcie/u_clk_rst_gen/u_pipe_clk/S[01]$

# PeakRDL regblock: field_combo / field_storage are unpacked structs whose
# members are each written by their own always_comb / always_ff. Legal SV
# (one longest static prefix per process); Verilator flags the whole variable:
# https://github.com/verilator/verilator/issues/4226 (reviewed 2026-10-13)
verilator ^%Warning-MULTIDRIVEN: csr\.sv:[0-9]+:[0-9]+: Variable written to in always_(comb|ff) also written by other process .*: '(field_combo|field_storage)'$

# PeakRDL regblock output (generated, rewritten by MakefileCSR): anonymous
# structs and long generated lines. Verible names no signal in these messages,
# so file + rule (reviewed 2026-10-14)
verible ^csr\.sv:[0-9:-]+ .*\[(typedef-structs-unions|line-length)\]$
verible ^csr_pkg\.sv:[0-9:-]+ .*\((CSR_DATA_WIDTH|CSR_MIN_ADDR_WIDTH|CSR_SIZE)\)\. .*\[explicit-parameter-storage-type\]$

# PCIE_2_1 attribute names (vendor names, kept as is: 2.rtl/README.md coding
# rules) (reviewed 2026-10-14)
verible ^src/pcie/pcie_core\.sv:[0-9:-]+ .*\(got: DISABLE_(ASPM_L1_TIMER|BAR_FILTERING|ERR_MSG|ID_CHECK|LANE_REVERSAL|LOCKED_FILTER|PPM_FILTER|RX_POISONED_RESP|RX_TC_FILTER|SCRAMBLING)\) .*\[positive-meaning-parameter-name\]$

# every unique case has a default, also a full one (our rule; in eduBOS5 an
# illegal opcode halts, an unknown store width writes nothing): unique checks
# that the items never overlap, the default that no value goes unhandled
slang ^src/.*\.sv:[0-9]+:[0-9]+: warning: .case[zx]?. marked .(unique|priority). has .default. label

# reset: data and address flops need no reset (our rule: control flops and
# flags do). These reach a select through a compare or an address decode. Each
# name is anchored to its instance path: the SoC (u_soc.) or eduBOS5 alone with
# RV32M (no prefix).
#   eduBOS5: operands, load/store offset, data address, ALU result and operand
#   signs, the divider's data path; the SoC: the instruction word from the RAM,
#   the TLP RAMs' read data (tx_pl_a_q, rx_pl_q: the DW0 a TLP's length comes
#   from, read before it is used) and eduBOS5's store data (dmem_wdat: the
#   tx.send count); PicoRV32 (CPU=picorv32): its read data, the RAM's read
#   data, the PCPI instruction word, and its multiplier's and divider's
#   operands (RV32M)
reset '(u_soc\.cpu\.)?(rs1_reg|rs2_reg|ls_offset_reg|dmem_addr|dmem_wdat|g_md\.(div_res|dvs|r_sh))'
reset '(u_soc\.cpu\.)?u_alu\.(alu_minus_reg|aluin_[12]_31_reg)'
reset 'u_soc\.(imem_rdat|ram_rdata|tx_pl_a_q|rx_pl_q|cpu\.mem_rdata_q)'
reset 'u_soc\.cpu\.(pcpi_insn|g_enable_mul\.pcpi_mul\.rs1|g_enable_div\.pcpi_div\.(dividend|divisor))'

# ---- iob, check-timing, methodology (added 2026-11-27, with the phases) ----
# iob: the link LEDs are slow status pins, not data: no I/O flop. led[3:2]
# are the inverted fw_pass and trn_link_up (RC_opensource.sv)
iob ^src/RC_opensource\.sv:[0-9]+: 'led_link_up\[[23]\]' output: driven by logic
# iob: PERST# is a reset, not data: it is ANDed with the MMCM lock into the
# reset synchronizer's clear (clk_rst_gen.sv)
iob ^src/pcie/clk_rst_gen\.sv:[0-9]+: 'perst_n' input: no flop takes it directly
# check-timing: PERST# has its false path (RC.common.xdc); the LEDs have no
# output delay, being slow status pins. The counts catch a new pin
check-timing ^no_input_delay: There is 1 input port with no input delay but user has a false path constraint\. \(MEDIUM\)$
check-timing ^no_output_delay: There are 2 ports with no output delay specified\. \(HIGH\)$
# methodology: the reset synchronizer's asynchronous clear is PERST# and the
# MMCM lock through one LUT; its release is synchronized (u_rst_sync0/1), a
# glitch can only assert the reset early
methodology ^LUTAR-1 Warning: LUT cell u_pcie/u_clk_rst_gen/u_rst_sync0_i_1, .* drives asynchronous preset/clear pin\(s\) u_pcie/u_clk_rst_gen/u_rst_sync0/CLR, u_pcie/u_clk_rst_gen/u_rst_sync1/CLR\.
# methodology: the SOC RAMs answer the next clock by design (the CPU and the
# Tx fetch take the data straight from the RAM), so no output register is merged
methodology ^SYNTH-6 Warning: The timing for the instance u_soc/(ram_reg_[0-9]+|rx_pl_reg|tx_pl_reg), implemented as a RAM block
